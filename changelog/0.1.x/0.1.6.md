# 0.1.6 — 2026-08-22

The framework gap was ~150 releases, so the server was rebuilt on a fresh `bunx @cyanheads/mcp-ts-core init` scaffold rather than migrated in place. Tool names, the `shift://status` URI, input and output shapes, annotations, the worker-ID pattern, and the coordination-protocol text are unchanged.

## Changed

- **Tool inputs are strict.** An argument key `shift_check_in` or `shift_check_out` does not declare is rejected by name instead of silently stripped, and both advertised `inputSchema`s carry `additionalProperties: false`.
- **The advertised `outputSchema` declares the error envelope** — success fields become optional and an `error` property is declared, so a client that validates `structuredContent` without first checking `isError` no longer rejects a failed call with `-32602`.
- **Every HTTP endpoint serves MCP protocol revision 2026-07-28** alongside the 2025-era revisions, and advertised JSON Schema is 2020-12 rather than draft-07.
- **`shift_check_in`'s unknown-worker failure is a declared error contract.** The wire error carries `data.reason: "unknown_worker"` and a recovery hint on both client surfaces; the message and the active-workers table embedded in it are unchanged.
- **The active-workers table renders the full ISO 8601 check-in timestamp** instead of `HH:MM` — a worker who checked in yesterday no longer reads as current. Affects `shift_check_in` text output and `shift://status`.
- **`ctx.log` lines reach the client** as `notifications/message`, gated by the client's `logging/setLevel`.
- **The Docker image runs `MCP_SESSION_MODE=stateless`.** The framework default is `auto`, which resolves to `stateful`; no handler here needs a session.
- **The worker store lives at `src/services/worker-store/worker-store.ts`**, moved out of `src/mcp-server/tools/definitions/`.

## Added

- **`resources/subscribe` and `resources/unsubscribe` are advertised and backed**, so the `shift://status` update fired on every check-in, session update, and check-out reaches subscribers on both protocol eras.
- **Smoke, tool-contract integration, and fuzz suites** alongside the unit tests.
- **`.mcpb` bundle packaging** — `manifest.json`, `bun run bundle`, and `bun run lint:packaging` — plus Claude Code and Codex plugin manifests.
- **Directory-based changelog** under `changelog/<major.minor>.x/`, with `CHANGELOG.md` regenerated by `bun run changelog:build`.
- **Docker healthcheck** against `/healthz`, and a `--platform=$BUILDPLATFORM` build stage so multi-arch `buildx` works from an arm64 host.
