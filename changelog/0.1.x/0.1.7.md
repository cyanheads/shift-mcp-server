# 0.1.7 — 2026-09-20

## Changed

- **`@cyanheads/mcp-ts-core` bumped `^0.12.3` → `^0.13.6`** across thirteen framework releases — see Dependencies for the security and dependency detail.
- **The framework skill tree moved from `skills/` to `framework-skills/`** — a server shipping a Claude Code or Codex plugin manifest no longer hands its own development skills to every installing agent.
- **`src/index.ts` declares `sessionMode: 'stateless'` in `createApp()`** — `MCP_SESSION_MODE` still overrides it when set; the server already ran stateless, this just makes it explicit in code.
- **The server card at `/.well-known/mcp.json` now publishes the resolved session mode** under the `_meta` key `io.github.cyanheads.mcp-ts-core/sessionMode`.
- **An invalid tool argument now rejects as `-32602` (`InvalidParams`)** with a structured envelope — `data.reason: "invalid_arguments"` and a schema-derived recovery hint, rendered as a `Recovery:` line in the error text. Previously the classification and payload differed.
- **A tool error's text closes with `(reason <reason>)`**, plus `· not retryable` when `data.retryable` is `false`.
- **Tool arguments pass an ordered pre-validation step before schema validation** — client-added keys (`_meta`, `tool_call_description`, `toolCallId`, underscore-prefixed keys) are dropped, an undeclared key whose case-style variant names a declared parameter is aliased onto it, and a JSON-stringified array is repaired and re-parsed once on failure. A call that previously failed on one of these shapes now succeeds.
- **A caller disconnecting mid-call classifies as `RequestCancelled` (`-32011`)** instead of an internal error.
